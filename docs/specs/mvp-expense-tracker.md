# MVP: Local Expense Tracker Web App

**Status:** Ready for implementation  
**Version:** 0.1  
**Date:** 2026-10-18  
**Product:** VMM Facility Management

## Objective

Build a small expense tracking web app that runs locally on the Facility Manager's Mac. The frontend and backend run together on the same machine and the FM uses the app in a browser. This is a web app, not a packaged desktop app.

## Technology and runtime

- Frontend: React + TypeScript.
- Backend: ASP.NET Core Web API in C#.
- Database: SQLite accessed with EF Core.
- The app binds only to localhost and is not accessible from other devices on the network.
- Provide one documented local start command or script that starts the frontend and backend together and opens the local web app in the browser.
- Persist the SQLite database in a user-writable application data directory, not in a temporary folder. Do not require internet access, Ollama, cloud services, or a desktop wrapper.

## MVP functionality

### Expense fields

Each expense has:

- **Amount:** required, greater than zero, INR, maximum two decimal places. Store as a decimal-safe value, not floating point.
- **Date:** required expense date, shown in the Mac's local date format. Future dates are not allowed.
- **Category:** required. Use this fixed list: Utilities, Maintenance & Repairs, Housekeeping, Security, Supplies, Other.
- **Description:** required, 1–500 characters.
- **Payment state:** required; Paid or Unpaid.
- **ID and timestamps:** generated by the app for record management.

No payee, payment method, notes, receipt, invoice, attachment, approval, or audit-history fields are included in this MVP.

### Create, read, and edit

- The main page lists expenses, newest date first, with date, description, category, amount in INR, and payment state.
- The FM can create an expense using a simple form.
- The FM can open and view an expense.
- The FM can edit an existing expense. Saving edits replaces the current values; a separate change-history UI is out of scope.
- Validate required fields and all field rules before saving. Show understandable field-level errors and a save confirmation.
- Keep the expense list and form usable after app restart; data is stored in SQLite.
- Deleting expenses is out of scope.

### PDF expense report

- Provide one **Export PDF report** action.
- Generate a PDF containing all expenses currently stored in the app, sorted newest date first.
- Include a report title, generation date, and a table with date, description, category, amount (INR), and payment state.
- Include total expenses, total Paid, and total Unpaid at the end of the report.
- Handle multiple pages with the table heading repeated on each page.
- The browser downloads the PDF to the user's local machine using its normal download behavior. Use a clear filename such as `VMM-Expense-Report-YYYY-MM-DD.pdf`.
- The PDF is a report of existing data; it does not change database records.

## Authentication and access

- This MVP supports one FM account on one Mac. On first launch, prompt the FM to create a username and password; do not ship default credentials.
- Store only a salted password hash in SQLite using ASP.NET Core Identity's password hasher. Never store or log the plain password.
- Require sign-in when the app is opened. After a successful login, use a short-lived local session for API requests; do not send the password on every request or keep it in browser storage.
- Provide a sign-out action. Password reset, multiple accounts, roles, and remote identity providers are out of scope.
- Bind only to localhost and do not expose the app to the LAN or public internet.

## Minimal API surface

Use the existing API conventions where available. At minimum, provide:

- `GET /api/expenses` — list all expense records.
- `GET /api/expenses/{id}` — read one record.
- `POST /api/expenses` — create a record.
- `PUT /api/expenses/{id}` — edit a record.
- `GET /api/expenses/report.pdf` — generate and return the PDF report.

Validate data in the backend as well as the UI. Return clear validation errors. Do not add search, category management, filters, pagination, CSV export, or other endpoints unless required by an existing app convention.

## Acceptance criteria

1. The FM can start the frontend and backend together on a Mac and open the app in a browser at a localhost address.
2. The app is not exposed on the local network.
3. The FM can create, read, and edit expenses with the specified fields and validation.
4. Invalid amounts, dates, categories, descriptions, or missing required fields are rejected with a clear message.
5. Expenses remain available after stopping and restarting the app.
6. The FM can download a multi-page PDF report containing all saved expenses and correct overall/Paid/Unpaid totals.
7. The FM can create the single local account on first launch, sign in, and sign out; the password is never stored in plain text.
8. No receipt storage, desktop packaging, internet dependency, or additional expense features are required for this MVP.
